# BOT_FUNCTIONAL_AUDIT.md

Документ фиксирует текущую карту возможностей MAX-бота СКУД и используется как чек-лист аудита. Это не PRD на будущие идеи, а рабочая спецификация того, что уже есть в коде и должно продолжать работать.

## Контур

- Backend: FastAPI (`app/main.py`) с роутами из `app/api/router.py`.
- Основной runtime приема MAX-событий: polling (`app/polling.py`) на проде `BOTSGSN`; webhook-роут `/api/webhooks/max` остается поддержанным.
- Данные: SQLite `data/attendance_bot.db`.
- Справочник сотрудников, роли, руководители, кабинеты, графики: Google Sheets и локальный кеш `employee_directory`.
- Роль пользователя определяется в `RoleResolver`: override из БД, затем активная строка Google Sheets, затем локальная `employee_directory`, затем технические префиксы, затем `employee`.
- Видимые MAX-ответы должны держать чат чистым: старые карточки удаляются/очищаются best-effort, callback-карточки редактируются.

## Роли

- `employee`: обычный сотрудник.
- `manager`: начальник отдела.
- `security`: служба безопасности.
- `hr`: HR.
- `admin`: администратор.
- `top_manager`: главный руководитель.

Пользовательские названия ролей должны отображаться по-русски через `app/domain/role_labels.py`.

## Общие возможности

- `/start`, `Начать`, `Старт`, `Главное меню` открывают актуальное главное меню и сбрасывают активный dialog state.
- `Обо мне` показывает ID MAX, chat ID, роль, данные из справочника, статус устройства и ссылку определения устройства.
- Старые или неизвестные callback-кнопки должны обновлять карточку актуальным главным меню, а не оставлять пользователя в “не понял команду”.
- Текстовые fallback-команды для верхнеуровневых кнопок должны работать, если MAX прислал текст вместо callback.
- Активные сценарии не должны блокировать навигацию в главное меню, `Обо мне`, `Мои опоздания` и другие явные разделы.

## Устройства

- В `Обо мне` есть текстовая ссылка `/device?user_id=<MAX_ID>`.
- `/device` определяет Android/iOS/unknown по browser user agent, включая iOS WebView/iPadOS через `MacIntel + maxTouchPoints`.
- `/api/device` сохраняет платформу в `user_bot_activity.device_platform`.
- Отчет `Устройства` для руководителей считает Android/iOS/unknown по реальным пользователям и должен включать определенные Android/iOS даже если устройство было сохранено через web API до следующего взаимодействия с ботом.

## Attendance-сценарии

### Опаздываю

- Доступно всем ролям, кроме `top_manager`.
- Пользователь выбирает согласующего.
- Выбирает дату `Сегодня` или `Завтра`.
- Нажимает `Указать причину`.
- Вводит причину вручную.
- Вводит время `Опаздываю с`.
- Бот создает late notice / attendance case и отправляет согласующему уведомление.
- Для manager/admin согласующим может быть `top_manager` или замещающий руководитель.

### Забыл карточку СКУД

- Доступно всем ролям, кроме `top_manager`.
- Пользователь выбирает согласующего.
- Вводит фактическое время прихода.
- Бот создает case и отправляет на согласование.

### Объяснение импортного случая

- Сотрудник видит личные cases.
- Для cases, ожидающих объяснение, выбирает причину.
- Выбирает согласующего.
- Бот создает approval и уведомляет manager/top_manager.

### Досрочный выход из отсутствия

- Для допустимого absence period case пользователь может сократить дату окончания.
- Изменение отправляется на повторное согласование.

## Согласования

- Manager/top_manager/admin/hr видят согласования согласно роли и зоне ответственности.
- Push-уведомление по согласованию открывает карточку, а не делает approve/reject сразу.
- Approve закрывает approval и уведомляет заявителя.
- Reject для `Опаздываю` и `Забыл карточку СКУД` требует комментарий отказа.
- История и просроченные доступны из раздела согласований.

## Замещения

- Manager/top_manager может создать draft замещения на период.
- Выбирается замещающий сотрудник.
- Выбирается причина и период.
- Можно передать курирование отделов.
- Замещающий должен согласовать или отклонить.
- Активные согласованные замещения расширяют видимость команд, согласований, cases и отчетов.
- Draft можно снять или продлить.

## СКУД и импорт

- Загрузка СКУД доступна manager/security/admin/top_manager.
- Поддерживаются Excel/CSV attachment flows через MAX.
- Если attachment не содержит прямого URL, бот пытается восстановить файл по message_id.
- Импорт создает attendance cases и daily records.
- Поддерживаются raw pass logs и summary reports.
- Сотрудники матчятся по справочнику, включая нормализацию ФИО.
- `top_manager` исключается из генерации ежедневных нарушений.
- История импортов доступна в СКУД-разделах.

## Отчеты

- Быстрые отчеты: неделя, месяц, квартал.
- Кастомный период: бот спрашивает дату начала и дату конца.
- Отчеты по отделам.
- Генерируются XLSX и PDF.
- Файлы отправляются в MAX, при необходимости используются public download URL.
- Callback на отчет должен отвечать быстро, генерация и отправка идут в фоне.
- Повторный отчет того же типа для пользователя очищает предыдущие report records/files.

## Аналитика

- `Сводка`: ожидающие согласования и активные cases.
- `Входы`: уникальные пользователи, старты, активность за 7 дней, последние пользователи, устройства в последних активностях.
- `Устройства`: Android/iOS/unknown по пользователям.
- `Неявки отделов`: top-manager view по absent cases.
- `По отделам`: division report.
- `Просроченные`: overdue approvals.

## Кабинеты и опломбирование

- Сотрудники с заполненным `Кабинет` получают reminder.
- Женщины: 17:10, мужчины: 17:55.
- Текст напоминает закрыть дверь и опломбировать кабинет.
- Кнопка `Спасибо за напоминание` подтверждает callback и удаляет/очищает reminder-карточку.
- Scheduler защищен leader-lease в `runtime_markers`, чтобы не отправлять пачку дважды.

## HTTP API

- `GET /api/health`: health status.
- `POST /api/webhooks/max`: MAX webhook.
- `GET /device`: страница определения устройства.
- `POST /api/device`: сохранение устройства.
- `GET /api/reports/{token}/download`: download XLSX.
- `GET /api/reports/{token}/download/pdf`: download PDF.
- `POST /api/imports/skud/csv`: импорт CSV.
- `GET /api/imports/skud`: список импортов.
- `POST /api/employees/directory/csv`: импорт справочника сотрудников.
- `GET /api/employees/directory`: список сотрудников.
- `GET /api/office-seal/photos/{filename}`: фото опломбирования, если включен старый photo-flow.

## Критические инварианты

- Каждая кнопка должна иметь обработчик action или явный forbidden response.
- Верхнеуровневые кнопки должны иметь text fallback.
- Role menu не должен показывать действие, запрещенное `ACTION_ALLOWED_ROLES`.
- Unknown callback должен обновлять меню, а не вести в тупик.
- Google Sheets active role должен перебивать устаревшую локальную `employee_directory`; explicit override сильнее Sheets.
- `top_manager` не должен видеть `Опаздываю` и `Забыл карточку СКУД` в главном меню.
- Реальные device detections Android/iOS должны попадать в `Устройства`.
- Тесты должны покрывать меню, action map, роль, device report, import/report flows, approval/rejection flows, substitutions, clean chat behavior.
